# StayCare 역할별 워크스페이스와 인수기준

## 공통 원칙

- 모든 화면은 tenant와 organization 범위 안에서만 데이터를 조회한다.
- 브라우저에 전달되는 데이터도 현재 역할의 업무범위로 제한한다.
- 근로자 개인 법률·의료·인권·개인송금 상세정보는 고용주·현지기관에 제공하지 않는다.
- 감사자는 화면뿐 아니라 API에서도 수정할 수 없다.
- 정부·EPS·출입국의 최종 승인은 관계기관이 수행하며 StayCare는 자료·기한·진행상태를 관리한다.
- 주요 변경은 application event, ticket event, audit event와 근로자 알림으로 기록한다.

## 1. 일반 근로자

경로:

```text
/{locale}/staycare/app
```

완료된 사용자 흐름:

1. 홈에서 현재 단계, 다음 행동, 기한, 전체 준비도를 확인한다.
2. 전체 생애주기를 현지 준비부터 귀국까지 단계별로 확인한다.
3. 정부 공식단계는 공식 링크로 이동하고 민간 준비단계는 직접 완료 처리한다.
4. 통신·체류행정·은행·송금·생활·귀국 서비스를 신청한다.
5. 신청번호, 현재 상태, 기관·제휴사 참조번호와 처리이력을 확인한다.
6. 여권·비자·계약서·교육·숙소·등록서류를 private Storage에 업로드한다.
7. 승인·반려·보완사유를 문서함과 알림에서 확인한다.
8. 일반·출입국·노동·주거·건강·통신·금융·송금·귀국 상담을 티켓으로 접수한다.
9. 티켓 우선순위, SLA, 담당자 안내와 처리이력을 확인한다.
10. AI 생활가이드·번역을 사용하되 민감 식별자는 입력하지 않는다.
11. 연락처, 숙소요약과 선호언어를 관리한다.
12. 알림을 확인하고 읽음 처리한다.

## 2. 세중 총괄 관리자

경로:

```text
/{locale}/staycare/admin
```

업무범위:

- 전체 활성 근로자와 위험도
- 전체 서비스 신청 처리
- 근로자 단계·상태·다음 행동·기한 변경
- 문서 승인·반려·보완요청
- 티켓 우선순위·담당부서·SLA·근로자 안내
- 출입국 사건·기한 확인
- 감사기록 조회
- DB와 환경변수 상용 준비상태 확인

## 3. 세중 변호사

기본 업무범위:

- 법률·노동·인권·고위험 체류 신청
- 노동·법률·인권·긴급 P0/P1 티켓
- 사건 검토에 필요한 계약·여권·비자·등록·의료 관련 문서
- 관련 근로자만 브라우저에 전달
- 일반 운영·환경설정·무관한 근로자 데이터 제외

## 4. 출입국 업무 관리자

기본 업무범위:

- 외국인등록
- 체류연장
- 주소변경
- 사업장변경
- 체류자격 변경 검토
- 출국·증명서 사건
- 관련 신청·티켓·여권·비자·계약·숙소·등록 문서
- 관련 근로자만 브라우저에 전달

## 5. 운영사 매니저

업무범위:

- 전체 운영량과 SLA
- 온보딩과 다음 행동
- 신청·문서·티켓·출입국 업무
- 제휴사 전달과 결과 회수
- 운영환경 준비상태
- 감사기록

## 6. 운영사 담당자

업무범위:

- 본인에게 배정되거나 아직 미배정된 신청
- 본인에게 배정되거나 아직 미배정된 티켓·출입국 사건
- 검수대기·보완요청 문서
- 위 업무에 연결된 근로자만 브라우저에 전달
- 전체 감사기록과 전체 환경설정 제외

## 7. 고용주 담당자

경로:

```text
/{locale}/staycare/portal
```

업무범위:

- 자기 사업장에 연결된 근로자의 단계·준비도·입국일·비자기한·다음 행동
- 자기 조직에 명시적으로 배정된 서비스 신청
- 근로자 또는 조직 단위 세중 협업요청
- 개인 법률·의료·인권·개인송금 상세정보 제외
- 상태 변경은 불가

## 8. 스리랑카 현지기관

업무범위:

- 자기 기관 후보자의 교육·서류·비자 후 출국준비
- 한국 측 인계에 필요한 입국예정일과 다음 행동
- 자기 조직에 배정된 업무
- 후보자 또는 기관 단위 세중 협업요청
- 한국 입국 후 개인 민감정보 제외
- 상태 변경은 불가

## 9. 제휴 서비스사

업무범위:

- 자기 조직에 배정된 신청만 조회
- 서비스 수행에 필요한 최소 제출정보
- 고객 추가정보 요청
- 승인·예약
- 완료 처리
- 반려와 사유
- 외부 참조번호
- 근로자에게 보일 메시지
- 자기 조직 밖 신청과 근로자 전체정보 접근 금지

## 10. 감사·품질관리

업무범위:

- 운영 KPI
- 신청·근로자·문서·티켓·출입국 사건
- append-only 감사기록
- 환경설정 상태
- 모든 수정 버튼 제거
- 모든 수정 API에서 권한 거부

## 역할별 회귀테스트

### 근로자

- 서비스 신청 후 신청목록과 상세에 즉시 표시되는가
- 문서 업로드 후 검수대기 상태로 표시되는가
- 상담티켓 생성 후 티켓번호와 SLA가 표시되는가
- 언어변경이 새로고침 후 유지되는가
- 알림 읽음 처리가 유지되는가

### 관리자

- 신청 상태와 근로자 안내가 근로자 앱에 반영되는가
- 문서 승인·반려 결과가 근로자에게 전달되는가
- 티켓 상태·우선순위·안내가 근로자에게 전달되는가
- 근로자 다음 행동 변경이 홈과 알림에 반영되는가

### 협력기관

- 고용주가 다른 사업장 근로자를 볼 수 없는가
- 현지기관이 다른 기관 후보자를 볼 수 없는가
- 제휴사가 다른 제휴사 신청을 볼 수 없는가
- 고용주·현지기관이 신청 상태를 직접 수정할 수 없는가
- 제휴사 결과가 근로자 신청 타임라인에 반영되는가

### 감사

- 화면에 수정버튼이 없는가
- 수정 API를 직접 호출해도 403이 반환되는가
