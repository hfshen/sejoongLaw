# StayCare 개인정보·보안·상용 전환 게이트

## 1. 보호대상 정보

StayCare는 다음 고위험 정보를 처리할 수 있다.

- 여권번호·여권 원문
- 외국인등록번호·등록증
- 비자·체류기간·입출국 정보
- 고용계약·임금·근로시간
- 숙소 주소·연락처·비상연락망
- 보험·산재·병원·건강정보
- 법률상담·노무상담·형사·인권 민원
- 결제·환불·비용부담자

따라서 일반 콘텐츠 사이트와 분리된 권한, 저장소, 로그와 운영절차가 필요하다.

## 2. 데이터 최소화

- 목록에는 여권번호·외국인등록번호 전체를 표시하지 않는다.
- 문서 원문 대신 검수상태·발급일·만료일·마스킹 값으로 운영한다.
- 고용주에게 개인 법률·건강·인권 상담 원문을 제공하지 않는다.
- 지정 수행팀에는 배정업무에 필요한 최소정보만 제공한다.
- 로그·Sentry·Analytics에 민감정보를 넣지 않는다.

## 3. 인증·권한

- Supabase Auth
- 조직·테넌트·멤버십 기반 RBAC
- 관리자·변호사·운영 PM MFA
- 민감문서 조회·다운로드·환불·대량내보내기 Step-up
- 계정 정지·회수·세션 만료
- UI 숨김이 아니라 서버와 RLS에서 거부

## 4. 문서 저장

- Supabase private bucket
- 원본 공개 URL 금지
- 짧은 만료 Signed URL
- 파일 유형·크기·악성파일 검사
- 버전·해시·업로더·검수자
- 조회·다운로드·내보내기 감사이벤트
- 계약종료·보존기간 만료 후 파기큐

## 5. 데이터베이스 RLS

테넌트와 조직을 기준으로 다음을 보장한다.

- 다른 테넌트 접근 차단
- 다른 고용주의 회원 접근 차단
- 근로자는 본인 데이터만 접근
- 수행팀은 배정 업무만 접근
- 감사자는 읽기만 가능
- 감사이벤트는 신뢰된 서버 또는 service role만 기록

## 6. 결제

- 카드번호·CVC 저장 금지
- 승인된 PG의 customer·subscription·payment reference만 저장
- 웹훅 서명검증
- 멱등키와 중복청구 방지
- 결제실패 재처리
- 환불 Step-up과 사유
- 법률사건 비용과 멤버십 비용을 별도 주문·계약으로 분리

## 7. 동의·계약

필요한 동의 버전을 기록한다.

- 서비스 이용약관
- 개인정보 수집·이용
- 민감정보 처리
- 제3자 제공
- 업무위탁
- 국외이전이 있는 경우 국외이전
- 마케팅 선택동의
- 고용주 또는 비용부담기관에 제공하는 정보범위

동의철회, 변경된 약관 재동의, 보존·파기 이력을 관리한다.

## 8. 실데이터 투입 전 필수 테스트

1. 역할별 허용·거부 자동테스트
2. 타 테넌트·타 고용주 접근 시도
3. 직접 URL·API·Storage 우회 테스트
4. Signed URL 만료 확인
5. 관리자 MFA·Step-up
6. 환불·가격·권한변경 감사로그
7. Excel 수식주입·마스킹
8. 웹훅 위조·중복·재전송
9. Sentry·서버로그 민감정보 점검
10. 백업·복구·계정회수·파기 훈련

## 9. 환경 분리

### Development

- 합성데이터만 사용
- 실제 전화번호·이메일·여권 금지
- 테스트 PG

### Preview / Staging

- 합성데이터 또는 명시적 테스트 계정
- 운영과 분리된 Supabase 프로젝트 권장
- 제한된 관리자만 접근

### Production

- 승인된 약관·개인정보 문서
- 운영 Supabase와 private Storage
- 도메인·HTTPS·보안헤더
- 백업·모니터링·사고통지
- 실제 PG와 알림공급자
