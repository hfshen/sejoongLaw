# Sejoong StayCare 보안·개인정보·컴플라이언스 기준

## 1. 문서의 목적

이 문서는 외국인 근로자의 여권, 체류정보, 고용정보, 건강·분쟁정보를 다루는 StayCare 플랫폼의 최소 안전기준을 정의한다. 실제 서비스 개시 전 세중의 법률검토와 개인정보보호 책임자의 승인이 필요하다.

## 2. 법적·업무적 경계

플랫폼은 다음 원칙을 제품과 약관에 반영한다.

- 플랫폼 자체가 취업·비자·승소 결과를 보장하지 않는다.
- 직업소개, 출입국 민원대행, 법률사무, 노무사무는 자격과 등록 범위에 따라 분리한다.
- 세중의 법률업무와 운영사의 생활·업무관리 역할을 계약과 화면에서 구분한다.
- 제휴기관의 상품·서비스는 제공주체와 비용을 명확히 표시한다.
- 운영사는 법률사건 수임의 성과나 수임료에 연동된 대가를 받지 않는다.

## 3. 개인정보 분류

### 일반 개인정보

- 이름, 생년월일, 국적, 성별
- 연락처, 이메일, 주소
- 고용주, 사업장, 직무, 근무상태
- 서비스 이용기록과 상담 이력

### 고유식별·신분정보

- 여권번호와 여권사본
- 외국인등록번호와 등록증 사본
- 비자번호 및 체류자격
- 출입국·체류 관련 문서

### 민감 또는 고위험 정보

- 건강검진, 질병, 장애, 산재
- 범죄·수사·구금·강제퇴거 관련 정보
- 임금·계좌·송금 관련 정보
- 가족관계와 가족초청 정보
- 위치, 긴급출동, 실종 관련 기록

## 4. 수집 최소화

- 서비스 단계별로 필요한 항목만 수집한다.
- 단순 일정관리에는 전체 여권이미지를 기본 노출하지 않는다.
- 목록화면에는 번호 전체 대신 마스킹값을 사용한다.
- 전문 파트너에게는 할당 업무에 필요한 최소필드만 제공한다.
- 건강·범죄·가족정보는 별도 동의와 접근권한을 적용한다.
- 계약이 종료되면 법정·계약상 보관근거가 없는 데이터를 파기한다.

## 5. 동의와 고지

최소한 다음 동의를 버전별로 저장한다.

1. 서비스 이용약관
2. 개인정보 수집·이용 동의
3. 민감정보 처리 동의
4. 고유식별정보 처리 동의
5. 제3자 제공 동의
6. 처리위탁 고지
7. 국외이전 동의 또는 고지
8. 마케팅 수신 동의 — 선택
9. 위치·긴급지원 동의 — 필요한 경우

동의기록에는 문서 버전, 언어, 시각, IP, 기기정보, 철회 여부를 저장한다.

## 6. 역할기반 접근권한

### 필수 원칙

- 기본 거부
- 테넌트 격리
- 조직과 배정업무 기반 접근
- 본인 데이터 접근
- 관리자 역할도 업무상 필요한 경우에만 원문 열람
- 변호사·행정사·노무사는 배정된 사건·업무만 열람
- 다운로드·내보내기는 별도 권한과 사유 입력

### 고위험 작업

다음 작업에는 MFA 또는 Step-up 인증을 적용한다.

- 여권·등록증 원문 다운로드
- 대량 내보내기
- 관리자 권한 부여
- 은행·건강·형사 관련 정보 열람
- 데이터 삭제 또는 보존기간 변경
- 구독 환불 및 금액수정
- 감사로그 내보내기

## 7. 파일 보안

- Supabase Storage 또는 동등한 비공개 객체저장소 사용
- 공개 버킷 금지
- 사용자·테넌트·문서 유형별 경로 분리
- 짧은 만료시간의 서명 URL
- 업로드 파일 형식·크기·악성파일 검사
- 파일 해시와 버전 저장
- 승인되지 않은 원본 교체 금지
- 다운로드 및 미리보기 이벤트 감사기록
- 필요 시 워터마크 삽입

## 8. 감사로그

다음 행위를 감사이벤트로 남긴다.

- 로그인·실패·MFA
- 회원 조회·수정
- 민감정보 조회
- 파일 업로드·다운로드·삭제
- 업무 담당자·마감일·상태 변경
- 티켓 긴급도·분류·에스컬레이션 변경
- 구독·청구·환불 변경
- 권한 부여·회수
- 파트너에게 정보 제공
- 데이터 내보내기와 파기

감사로그는 일반 업무데이터와 분리하고 운영자가 임의 수정할 수 없도록 설계한다.

## 9. 티켓과 긴급대응

### P0

- 생명·신체 위험
- 실종·구금
- 중대 사고
- 자해·타해 위험

플랫폼은 긴급기관의 대체수단이 아니며, 즉시 112·119·해당 기관 연결과 내부 비상연락을 병행한다.

### P1

- 체류기한 임박
- 강제퇴거·출국명령
- 중대 임금체불·산재
- 여권 압류 또는 이동 제한 의심

P1 티켓은 운영 PM과 세중 지정담당자에게 자동 에스컬레이션한다.

## 10. 데이터 보존과 파기

- 정보유형별 보존기간 표를 운영한다.
- 계약종료 즉시 삭제가 아니라 법적보관·분쟁대응·회계증빙 여부를 분리한다.
- 파기는 파일, 데이터베이스, 검색인덱스, 캐시, 백업의 순차처리를 포함한다.
- 백업 파기는 보존주기에 맞춰 자동 만료한다.
- 파기결과를 감사로그에 남긴다.
- 회원에게 열람·정정·삭제·처리정지 요청 채널을 제공한다.

## 11. 국외이전과 현지 운영

스리랑카 현지 운영자 또는 콜센터가 접근할 경우 다음을 사전 확정한다.

- 이전 국가와 수탁자
- 이전 항목
- 이용 목적
- 이전 시점과 방법
- 보유기간
- 거부 방법과 불이익
- 재위탁 여부
- 접근통제와 사고통지 의무

현지 담당자에게 전체 여권·등록정보를 기본 제공하지 않고 업무별 최소화 화면을 제공한다.

## 12. 구독·결제 보안

- 카드번호·CVC 직접 저장 금지
- 승인된 PG의 결제수단 토큰 사용
- 청구금액 변경 이력 저장
- 관리자 임의 환불은 이중승인 적용 검토
- 결제웹훅 서명검증과 재처리 방지
- 멱등키 사용
- 미납과 서비스중지 상태 분리
- 긴급·인권 채널은 미납만으로 즉시 차단하지 않음

## 13. 운영사 위탁관리

세중과 운영사 사이에 최소한 다음 내용을 문서화한다.

- 위탁업무 목적과 범위
- 재위탁 승인
- 접근 가능한 개인정보 항목
- 직원 교육과 비밀유지
- 계정발급·회수
- 로그와 점검권
- 사고통지 시간
- 계약종료 시 반환·파기
- 현장출동과 통역 녹취 정책
- 월간 보안·개인정보 운영보고

## 14. 개발·배포 기준

- 환경별 데이터 분리
- 개발·데모에는 합성데이터 사용
- 비밀값은 Vercel/Supabase 환경변수로 관리
- PR 리뷰와 CI 통과 후 배포
- 의존성·정적분석·취약점 검사
- 데이터베이스 마이그레이션 롤백 계획
- 배포 전 RLS 검증
- 에러로그에 여권번호·등록번호·건강정보 기록 금지
- Sentry 등 외부 모니터링 전송항목 마스킹
