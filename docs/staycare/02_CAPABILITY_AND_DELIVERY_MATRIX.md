# Sejoong StayCare 기능·구축 매트릭스

## 1. 구축 단계

### Phase 0 — 합성데이터 레퍼런스 앱

목적은 사업 당사자들이 실제 운영 흐름과 역할을 화면으로 확인하는 것이다.

- 공개 제품 소개
- 역할별 데모 포털
- 근로자 목록과 상세카드
- 입국·정착 체크리스트
- 업무·민원·구독·파트너·감사로그 화면
- 합성데이터만 사용
- 실제 결제·정부시스템·법률사건 연동 없음

### Phase 1 — 20~50명 파일럿

- Supabase Auth 및 조직별 권한
- 실회원 초대와 동의
- 문서 메타데이터 및 암호화 저장
- 업무·티켓·알림
- 구독·청구 상태
- 운영사와 세중의 역할분리
- 월간 운영보고
- 개인정보 접근 감사로그

### Phase 2 — 고용주·파트너 확장

- 고용주 포털
- 파트너 포털
- 서비스 카탈로그와 배정
- SLA·비용·처리증빙
- 체류·고용·보험·숙소 만료엔진
- 대량 업로드와 데이터 검증
- 전자서명 및 동의 버전관리

### Phase 3 — 상용화

- 승인된 PG 구독결제
- 환불·미납·정산
- 다국어 콘텐츠 CMS
- 알림톡·SMS·이메일·푸시
- 보고서 PDF/Excel
- 고객사별 화이트라벨
- 장애·보안·백업·복구 운영
- 데이터 보존·파기 자동화

## 4. 데이터 도메인

- Tenant: 세중 서비스 단위
- Organization: 세중, 운영사, 고용주, 파트너
- Membership: 사용자와 조직·테넌트·역할 연결
- Worker: 근로자 기본 및 체류정보
- EmployerAssignment: 고용주·사업장·직무·계약 연결
- Document: 문서 메타데이터와 저장경로
- Workflow: 국가·비자·업종별 업무 템플릿
- Task: 담당자·마감일·상태·증빙
- Ticket: 민원·긴급도·분류·에스컬레이션
- Subscription: 플랜·기간·상태·부담주체
- Invoice: 청구·결제·환불 상태
- PartnerService: 전문서비스·지역·SLA·가격
- AuditEvent: 조회·변경·다운로드·내보내기 기록
- Consent: 약관·개인정보·민감정보 동의 버전
- Notification: 채널·템플릿·발송·수신 결과

## 5. 권한모델

| 역할 | 범위 |
|---|---|
| super_admin | 전체 테넌트 및 정책 |
| sejoong_admin | 세중 조직과 가입·매출·운영 전체 |
| sejoong_lawyer | 배정된 법률티켓과 필요한 회원자료 |
| operator_manager | 운영대상 전체, 담당자·SLA·리포트 |
| operator_agent | 배정 회원과 업무·티켓 |
| employer_admin | 자사 소속 근로자의 제한된 운영정보 |
| worker | 본인 정보·동의·문서·티켓 |
| partner_specialist | 배정 업무에 필요한 최소자료 |
| auditor | 승인된 기간의 읽기전용 로그·증빙 |

권한은 UI 숨김이 아니라 서버와 데이터베이스 RLS에서 검증한다.

## 6. 알림 규칙

### 마감알림

- 120/90/60/30/14/7/3/1일 전
- 담당자와 회원에게 서로 다른 문구 사용
- 이미 완료된 업무에는 발송하지 않음
- P1 이상 미확인 시 관리자에게 자동 승격

### 티켓알림

- P0: 즉시 관리자·비상연락망
- P1: 15분 미확인 시 운영 PM, 30분 미확인 시 세중 관리자
- P2: 4시간 미확인 시 담당자 재알림
- P3: 1영업일 미응답 시 운영 PM 알림

## 7. 비기능 요구사항

### 보안

- 모든 민감정보 접근 감사
- 최소권한 RBAC와 RLS
- 파일 다운로드 만료 URL
- 운영자 MFA
- 내보내기 워터마크와 사유입력
- 보존기간과 파기작업 기록

### 성능

- 운영 대시보드 초기표시 2.5초 이내 목표
- 목록 검색 1초 이내 목표
- 2,000명 테넌트까지 페이지네이션 기반 운영
- 대량 업로드 비동기 처리

### 가용성

- 파일럿 99.5%, 상용 99.9% 목표
- 일일 백업과 복구훈련
- 외부 메시지·결제 장애 시 재처리 큐
- 감사로그는 업무 트랜잭션과 분리 저장 검토

### 접근성·언어

- 모바일 우선
- WCAG 2.1 AA 기준 목표
- 한국어·영어·싱할라어 우선
- 날짜·통화·전화번호 국가별 형식
- 쉬운 문장과 아이콘 병행

## 8. 개발 완료 정의

각 이슈는 다음 조건을 충족해야 완료로 본다.

- 승인된 사용자 시나리오 구현
- 권한검사 및 실패경로 포함
- 로딩·빈상태·오류상태 포함
- 모바일·데스크톱 확인
- 단위 또는 통합테스트
- 감사이벤트 필요 여부 확인
- 개인정보 수집항목 검토
- 운영 매뉴얼 또는 화면 도움말 갱신
- 배포 및 롤백 절차 확인
